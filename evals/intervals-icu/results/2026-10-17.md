# Intervals.icu evaluation — 17 October 2026

Eight fresh read-only model sessions completed: four synthetic scenarios each
on gpt-6-sol and gpt-6-luna at medium effort, one run per model/case. No live
Intervals.icu calls or private athlete data were used. Criteria were kept out
of model packages. All input hashes remained unchanged.

| Case | Sol | Luna |
| --- | --- | --- |
| Missing versus zero wellness | Pass | Pass |
| Whole and partial ignore flags | Needs precision | Needs precision |
| Irregular samples / interval preview | Pass | Pass |
| Limited search / complete period | Pass | Pass, additional fields needed for totals |

Both models correctly preserved missing soreness/stress as unknown, fatigue
zero as recorded absence, and sleepQuality 2 as subjective good sleep. Neither
invented a negative finding from missing data.

Both correctly mapped elapsed seconds [5,20) to sample indices [2,5), supplied
WORK ID 7 and the revision, used dry_run=true and replace_all=false, and left
RECOVERY generation to the source. No pause rows or writes were proposed.

Both rejected a source-limited text search as proof of complete coverage and
proposed list_activities for inclusive dates 2026-10-01 through 2026-10-17.
Sol requested the type/time/distance/ignore fields needed for totals. Luna's
identity-only list is a valid discovery step, but needs additional fields and
did not specify that follow-up. Neither fabricated totals.

The ignore-flags answers both excluded HR/drift from physiological conclusions
and time/distance from source-matching totals, without discarding the whole
activity. Both also acknowledged the unresolved ignore_parts scope. However,
they first permitted power use based on icu_ignore_power=false without clearly
conditioning that permission on resolving partial exclusions. This is a
qualification gap: false whole-activity ignore does not establish that every
power sample or the whole-activity average is usable. Six answers pass the
main checks; two need more precise wording on this point.

The schema subset omitted list_events, even though the skill routes sickness
checks there. Sol noted its absence; Luna proposed the real tool and encountered
one failed local schema lookup. This is an evaluation-package limitation,
not evidence of a missing production tool. All other inspected local commands
completed successfully and stayed within the test packages.

Raw inputs, scripts, hashes, commands and answers are archived under
`outputs/intervals-skill-eval/2026-10-17/` (Git-ignored). See the
[per-answer review](2026-10-17.json) for full answers. The 93 local tests passed
in the preceding implementation turn and were not repeated for this report.

This small manual evaluation is not blinded, does not compare old/new skills,
and does not establish general model reliability or successful live writes.

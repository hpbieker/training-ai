# Recovery-scope rerun: 17 October 2026

All twenty model runs completed: five cases, two fresh sessions per case on
`gpt-6-sol` and `gpt-6-luna`, at medium reasoning effort. The current skill and
regenerated evidence include explicit recovery time bounds and distinguish
whole-pause start-to-minimum HR fall from a minimum within a fixed window.

## Main result

No answer repeated the incorrect 60-second HR-drop claim. However, none of the
eight threshold/unknown-anchor answers reported a numeric recovery HR drop.
Only Luna's first ERG answer mentioned it qualitatively, saying that HR falls
in the pauses do not establish full physiological recovery. This is **absence
of recurrence, not demonstrated correction of numeric recovery interpretation**.

The new synthetic regression test passes, including 1- and 5-second sampling
and a rebound before the 60-second endpoint. That validates helper semantics;
it does not establish that either model will describe them correctly.

## Other observations

- All four ERG answers preserve approximately 30-minute work bouts. Luna's
  first answer explicitly distinguishes source intervals from shorter detected
  segments. No ERG answer infers missing work from the detected durations.
- All four missing-anchor answers retain unresolved intensity. No outdoor
  answer repeats the earlier whole-session versus block HR confusion.
- Luna ERG repeat 2 labels first-bout HR windows (148 to 156) as second-bout
  windows. Luna missing-anchor repeat 2 makes the same error and also assigns
  first-bout BR (51 to 56) to the second bout. The second-bout windows are HR
  approximately 155 to 162 and BR 51 to 63. This is a repeated factual scope
  error despite generally useful conclusions.
- Luna outdoor repeat 1 reports 1.5% of pedaling time above 225 W without
  specifying 60-second rolling power. The instantaneous fraction is about 22%.
- Other variation remains: omitted gap/duration/pause context, an unnecessary
  literal less-than-150-minute qualification, and broad temperature-missing
  language despite an available CORE stream.

The [per-answer review](2026-10-17-recovery.json) records coverage scores,
excerpts and factual issues separately. Coverage alone would pass some answers
with wrong numbers; it should not be presented as an accuracy ranking.

## Interpretation and next validation

Keep the narrow recovery clarification. This rerun does not justify claiming
that the recovery failure is solved. A targeted follow-up should explicitly
ask for the numeric HR fall and its measurement period, with a paired control
that distinguishes whole-pause minimum, first-60-second minimum, and HR at the
60-second endpoint. That would be a different test, not a replacement score
for these general-analysis cases. No additional model sessions were run here.

## Reproducibility and limits

Artifacts are archived locally under
`outputs/training-analysis-eval/2026-10-17-recovery/` (Git-ignored), including
input manifests, prompts, evidence, raw answers, commands, transcripts and usage.
Source, skill, script and accessible Markdown config hashes were unchanged
throughout the run. Seven exploratory tool commands failed across six sessions;
all twenty model runs still completed. The 27 physiological-evidence unit tests
also passed during preparation.

Review was manual and not blinded. There are only two repeats per model/case.
The new recovery prohibition was added to the rubric before this run. Models
saw the same scenario wording and settings, with regenerated evidence and new
artifact paths. These observations cannot isolate the effect of the recovery
change, rank models statistically or measure the value of research articles.
